Why you need this

This chapter teaches you to write QICK programs for spin-qubit experiments: how a program is structured, how pulses, readouts and triggers are placed on the timeline, how sweeps run in hardware, how data comes back, and how to branch on a measurement. The examples use the tProc v2 API (AveragerProgramV2) of QICK 0.2.436, following the official tutorials . Every example is written for the 4x2's two generators and two readouts.

The shape of every program

from qick.asm_v2 import AveragerProgramV2, QickSweep1D, QickSpan

class MyExperiment(AveragerProgramV2):
    def _initialize(self, cfg):
        # runs once, in Python, when the program is compiled:
        # declare channels, define envelopes and pulses, configure readouts, add loops
        ...
    def _body(self, cfg):
        # describes ONE shot's timeline; the tProcessor repeats it reps × loops times
        ...

prog = MyExperiment(soccfg, reps=1000, final_delay=10.0, cfg=cfg)
data = prog.acquire(soc, rounds=1)
  • _initialize() runs on the Python side; _body() is translated into tProcessor instructions and executed in hardware .
  • reps repeats the body inside the tProcessor; rounds repeats the whole program from Python (useful to interleave long acquisitions with drift checks).
  • final_delay (µs) is the idle time added at the end of each shot: for spin qubits this is where you put re-initialisation or waiting for the reservoir, unless your sequence does it explicitly.
  • Units: MHz, µs, degrees, gain in [−1, 1].

Declaring channels

self.declare_gen(ch=0, nqz=1)             # DAC_B, Nyquist zone 1 (readout carrier)
self.declare_gen(ch=1, nqz=2)             # DAC_A, zone 2 (e.g. a 6 GHz EDSR tone)
self.declare_readout(ch=0, length=2.0)    # ADC_D, 2 µs readout window

Envelopes and pulses

self.add_gauss(ch=1, name='g', sigma=0.01, length=0.05)   # 50 ns Gaussian envelope
self.add_pulse(ch=1, name='x90', style='arb', envelope='g',
               freq=cfg['f_q'], phase=0, gain=cfg['g_x90'])
self.add_pulse(ch=1, name='y90', style='arb', envelope='g',
               freq=cfg['f_q'], phase=90, gain=cfg['g_x90'])  # same pulse, 90° phase
self.add_pulse(ch=0, name='ro', style='const', freq=cfg['f_ro'],
               ro_ch=0, length=cfg['ro_len'], phase=0, gain=cfg['g_ro'])
self.add_readoutconfig(ch=0, name='roc', freq=cfg['f_ro'], gen_ch=0)
self.send_readoutconfig(ch=0, name='roc', t=0)

Envelope helpers include add_gauss, add_cosine, add_triangle, add_DRAG and add_envelope (your own I and Q arrays) . Pulse styles are const, arb and flat_top (Chapter 33). Passing ro_ch to the readout pulse and gen_ch to the readout configuration makes their frequencies match exactly (Chapter 36).

Placing events on the timeline

Inside _body(), times are relative to a reference time that you move forward as the shot proceeds:

def _body(self, cfg):
    self.pulse(ch=1, name='x90', t=0)            # at reference time
    self.delay_auto(t=cfg['tau'])                 # move the reference to the end of all
                                                  # pulses so far, plus tau
    self.pulse(ch=1, name='x90', t=0)
    self.delay_auto(t=0.05)
    self.pulse(ch=0, name='ro', t=0)              # readout carrier
    self.trigger(ros=[0], pins=[0], t=cfg['tof']) # start the readout window after the
                                                  # time of flight; also pulse PMOD0_0
  • pulse(ch, name, t) schedules a pulse at time t after the current reference.
  • trigger(ros=[...], pins=[...], t) starts readout windows and pulses PMOD trigger pins.
  • delay(t) moves the reference by t; delay_auto(t) moves it to the end of the last scheduled pulse or readout window, plus t.
  • wait(t) / wait_auto() make the processor pause until a time, needed before reading a measurement result for feedback.

QICK warns if two pulses on one generator overlap; the tips tutorial recommends delay_auto() to space them .

Sweeps in hardware

Declare a loop and attach swept parameters to it; the tProcessor runs the loop and updates the parameters without Python :

def _initialize(self, cfg):
    self.add_loop('len_loop', cfg['steps'])            # first loop declared = outermost
    self.add_pulse(ch=1, name='drive', style='const', freq=cfg['f_q'], phase=0,
                   gain=cfg['g'], length=QickSweep1D('len_loop', 0.01, 1.0))  # 10 ns → 1 µs
    ...
# after running:
lengths = prog.get_pulse_param('drive', 'length', as_array=True)   # actual, quantised values

Several loops nest in declaration order; QickSpan('loop', step_total) adds an increment per loop so a parameter can depend on several loops. Times, frequencies, phases and gains can all be swept. Always read back the actual values with get_pulse_param(), because they are quantised.

Getting data back

  • acquire(soc, rounds=...) returns, for each readout, an array with one I/Q pair per sweep point, averaged over reps. With threshold= and angle= it classifies every shot first and returns the fraction above threshold; get_shots() returns per-shot results .
  • acquire_decimated(soc, rounds=...) returns time traces; pair with get_time_axis().
  • Data shapes follow the loop order: (reps, outer loop, inner loop, …, I/Q) for raw data.

Feedback: branching on a measurement

def _body(self, cfg):
    self.pulse(ch=0, name='ro', t=0)
    self.trigger(ros=[0], pins=[0], t=cfg['tof'])
    self.wait_auto(cfg['read_wait'])          # processor waits until the result is ready
    self.read_and_jump(ro_ch=0, component='I', threshold=cfg['thr'],
                       test='>=', label='SKIP')
    self.pulse(ch=1, name='x180', t=0)        # only if I < threshold: e.g. active reset
    self.label('SKIP')

The QICK feedback tutorial shows how to measure the needed read_wait by comparing the value read by the processor with the buffered value, and how to rotate the readout phase so the decision is made on one quadrature . Lower-level instructions (read_input, cond_jump, registers, data memory) allow more complex logic such as counters, majority votes or adaptive sweeps.

A spin-qubit example: EDSR Rabi with an external plunger AWG

The 4x2 cannot hold a plunger level (Chapter 29), so here an external DC-coupled AWG plays the plunger pulse (load → manipulate → PSB readout point), started by a PMOD trigger. The 4x2 plays the EDSR burst on generator 1 and the readout carrier on generator 0:

class EDSRRabi(AveragerProgramV2):
    def _initialize(self, cfg):
        self.declare_gen(ch=0, nqz=1)                       # readout carrier, DAC_B
        self.declare_gen(ch=1, nqz=cfg['nqz_q'])            # EDSR drive (or IF), DAC_A
        self.declare_readout(ch=0, length=cfg['ro_len'])    # ADC_D
        self.add_loop('t', cfg['steps'])
        self.add_pulse(ch=1, name='burst', style='const', freq=cfg['f_q'], phase=0,
                       gain=cfg['g_q'], length=QickSweep1D('t', cfg['t0'], cfg['t1']))
        self.add_pulse(ch=0, name='ro', style='const', freq=cfg['f_ro'], ro_ch=0,
                       length=cfg['ro_len'], phase=0, gain=cfg['g_ro'])
        self.add_readoutconfig(ch=0, name='roc', freq=cfg['f_ro'], gen_ch=0)
        self.send_readoutconfig(ch=0, name='roc', t=0)

    def _body(self, cfg):
        self.trigger(pins=[1], t=0)                 # PMOD0_1 starts the AWG plunger sequence
        self.delay(cfg['t_manip'])                  # AWG reaches the manipulation point
        self.pulse(ch=1, name='burst', t=0)         # EDSR burst of swept length
        self.delay(cfg['t_to_readout'])             # AWG moves to the PSB readout point
        self.pulse(ch=0, name='ro', t=0)
        self.trigger(ros=[0], t=cfg['tof'])

The AWG's sequence must be designed to match these delays, and the trigger latency between the 4x2 and the AWG must be measured and compensated (Chapter 30). With DC-coupled outputs (a modified board or a ZCU216), the plunger pulses would simply be a third pulse in the same program, which is what spinQICK does .

Common mistake

Reading data shapes wrongly. With nested loops, the outermost declared loop changes slowest. Print the shape of the returned arrays and of get_pulse_param(..., as_array=True) the first time you run any new program.

Check yourself

1. In a Ramsey experiment, how would you implement "virtual detuning" in QICK without changing the drive frequency?

Show answer
Sweep the phase of the second X/2 pulse together with the free-evolution time: phase = 360° × \(f_{\text{virt}}\) × τ. With a loop over τ, use QickSweep1D for both the delay and the second pulse's phase, so the fringes appear at \(f_{\text{virt}}\).

2. Why do you need wait_auto() before read_and_jump() but not before a normal pulse?

Show answer
Normal commands are timestamped and queued; the processor can issue them long before they play. A branch depends on a measurement result that only exists after the readout window ends and the result propagates, so the processor itself must wait until then.
Summary
  • Programs define pulses and readouts in _initialize() and one shot's timeline in _body(); reps and loops run in hardware.
  • Place events with pulse, trigger, delay, delay_auto; wait with wait/wait_auto before reading results.
  • Sweep any parameter with add_loop + QickSweep1D/QickSpan; read back actual values.
  • acquire() for I/Q per point (optionally thresholded), acquire_decimated() for traces.
  • Feedback with read_and_jump; external AWGs are triggered with PMOD pins when baseband pulses are needed.
