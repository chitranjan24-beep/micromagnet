Why you need this

PYNQ is the software layer that makes the 4x2 usable from Python. It boots Linux on the ARM cores, runs a Jupyter server you open in your browser, loads FPGA designs at run time, and gives Python objects for every hardware block. QICK is a Python package built on top of it. Understanding PYNQ means you can set up the board on your network, install software, move files, recover from mistakes, and know which problems belong to Linux, which to PYNQ and which to QICK .

What PYNQ is

PYNQ ("Python productivity for Zynq") is an open-source framework from AMD consisting of:

  • a Linux image (Ubuntu-based) for the board's ARM cores, distributed as an SD-card image per board;
  • a Jupyter server (JupyterLab) on the board, so the board is programmed from a browser;
  • the pynq Python package, which loads overlays and provides drivers: MMIO register access, DMA buffers, GPIO, interrupts, clock control, and RFSoC-specific packages xrfdc (RF data converters) and xrfclk (clock chips);
  • example notebooks and a base overlay for each board.

The RFSoC-specific parts (board images, base overlays and notebooks for the 4x2, 2x2 and ZCU111) live in the RFSoC-PYNQ project . The SDR book's Notebook Set A introduces Jupyter, plotting and the PYNQ framework on RFSoC boards .

Jupyter in two minutes

A notebook is a document of cells. Code cells run Python on the board when you press Shift+Enter, and their output (text, plots) appears below. Markdown cells hold notes. The kernel is the Python process that keeps your variables between cells; restarting it clears everything, including the connection to the hardware. JupyterLab adds a file browser, terminals (a Linux shell on the board) and text editors in the same browser tab.

Common mistake

Running two notebooks that both create a QickSoc (or load overlays) at the same time. Each one reprograms the PL and expects to own it. Use one notebook per board at a time, or run QICK as a server (Pyro4, Chapter 37) and connect clients to it.

The boot process and the SD card

  1. At power-on, the boot ROM reads the boot mode switch (set to SD) and loads a first-stage boot loader from the SD card's boot partition.
  2. The boot loader configures the PS, loads a default bitstream into the PL (the green DONE LED) and starts U-Boot, which starts the Linux kernel.
  3. Linux mounts the SD card's root file system, starts networking (Ethernet and the USB "gadget" at 192.168.3.1), the Jupyter server and the OLED status display.

The SD card is the board's disk. Keep a spare card with a known-good image, and back up your notebooks regularly: SD cards wear out and can be corrupted by switching power off during writes. Shut the board down cleanly (sudo shutdown -h now in a terminal, or the Jupyter menu) before switching it off.

Networking for a lab

  • USB gadget: plug the micro-USB 3.0 cable into a PC; the board appears as a network adapter and is at 192.168.3.1. Fine for first use.
  • Ethernet with DHCP: the board gets an address from your network; the OLED shows it.
  • Static IP / private network: many labs put instruments on a separate network switch with fixed addresses, connected to the measurement PC through a second network card. This avoids IT restrictions and keeps measurement traffic local. QICK's quick-start guide explains static IP configuration .
  • SSH: log in with ssh xilinx@<board-ip> (default user xilinx, password xilinx) for a shell; copy files with scp. Change the default password if the board is on a shared network.

Overlays in practice

An overlay is a .bit plus .hwh (Chapter 27). Loading one in Python takes a few seconds:

from pynq import Overlay
ol = Overlay("base.bit")      # programs the PL with the base design
print(ol.ip_dict.keys())      # names of the IP blocks in the design

PYNQ parses the .hwh and attaches a Python driver to each IP block (generic or specialised), so ol.<block_name> gives you an object with its registers. When QICK starts, it does the same with its own bitstream and builds higher-level objects (generators, readouts, tProcessor) from what it finds .

The 4x2 base overlay and its notebooks

The PYNQ image ships a base overlay with the RF data converters, the PL DDR4 controller, two PMOD I/O processors (small MicroBlaze CPUs), and GPIO for the LEDs, buttons, switches and SYZYGY port . Its notebooks are a good first tour:

  • 01_rf_dataconverter_introduction, 02_rf_spectrum_analysis, 03_rf_spectrum_sweep: generate tones, capture ADC data, compute and plot spectra.
  • buttons_leds_switches, pl_ddr4, register_map_intro, syzygy_loopback: board I/O and register access.

Run them before installing QICK: they confirm that your converters, clocks and network work, and they show the same hardware through PYNQ's lower-level API.

Installing software on the board

The board runs a normal Linux with Python and pip, so packages are installed as on any Linux machine (with internet access through your network, or by copying wheel files). QICK is installed with pip from its repository, and its first demo notebook automates this . QICK states which PYNQ image versions it supports; at the time of writing it recommends PYNQ 3.0.1 for the 4x2 and does not yet support PYNQ 3.1 . Check the QICK quick-start page before updating the SD image.

On the 4x2

A clean setup sequence: (1) flash the PYNQ image QICK recommends; (2) boot, connect over USB, run the base-overlay RF notebooks with a DAC looped back into an ADC through a 20 dB attenuator; (3) set up Ethernet and SSH; (4) install QICK and run its first demo. Chapter 34 continues from step 4.

Check yourself

1. Which part of the system answers when you open http://192.168.3.1/lab?

Show answer
The Jupyter server running under Linux on the board's ARM cores (the PS), reached through the USB Ethernet gadget.

2. You restart the Jupyter kernel in the middle of a QICK session. What is lost?

Show answer
All Python variables, including the QickSoc object; you must recreate it (which reloads or reconnects to the firmware). The PL keeps its configuration until reprogrammed, but the Python side forgets it.
Summary
  • PYNQ = Linux image + Jupyter + Python package for overlays and hardware access + example notebooks.
  • Boot from SD; connect at 192.168.3.1 (USB) or the OLED-reported IP (Ethernet); SSH as xilinx.
  • Overlay() programs the PL and maps IP blocks to Python objects.
  • Run the base overlay RF notebooks first; install the QICK-recommended PYNQ image (3.0.1 for the 4x2 at the time of writing).
