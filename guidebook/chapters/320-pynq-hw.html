Why you need this

QICK hides most hardware details, but when something does not work, or when you want to test the converters directly, you will drop down to PYNQ's lower-level tools: reading registers, capturing raw ADC data, changing converter settings, checking clock lock. This chapter shows those tools with short examples, then maps the AMD SDR book's nine sets of hands-on notebooks onto what a qubit experimentalist should learn from each.

Registers: MMIO

Every AXI-Lite peripheral in the PL appears as a block of 32-bit registers at a physical address (Chapter 25). PYNQ's MMIO class maps such a block into Python:

from pynq import MMIO
regs = MMIO(base_addr, 0x1000)   # base address and size, from the overlay's ip_dict
regs.write(0x10, 12345)           # write register at offset 0x10
value = regs.read(0x14)           # read register at offset 0x14

Overlay drivers do this for you; for example ol.ip_dict lists each block's base address, and many drivers expose a register_map with named fields (the 4x2 base overlay has a register_map_intro notebook) . Each access from Python costs of order a microsecond, so MMIO is for configuration, never for timing.

Bulk data: allocate and DMA

DMA engines need physically contiguous memory that both Linux and the PL can access. PYNQ provides it with allocate, which returns a NumPy array backed by such memory:

import numpy as np
from pynq import allocate
buf = allocate(shape=(16384,), dtype=np.int32)
dma = ol.axi_dma_0                 # a DMA engine in the overlay (name depends on the design)
dma.recvchannel.transfer(buf)      # PL → memory
dma.recvchannel.wait()
data = np.array(buf)               # copy out, then free
buf.freebuffer()

QICK uses this mechanism internally for loading tProcessor programs and envelopes and for reading readout buffers .

The RF data converters: xrfdc

The xrfdc driver exposes the RF Data Converter IP as tiles and blocks with properties you can read and set. A few examples:

rf = ol.usp_rf_data_converter_0           # name in QICK's and most designs
dac = rf.dac_tiles[0].blocks[0]           # DAC tile 0 (AMD tile 228), block 0 = DAC_B on the 4x2
print(dac.NyquistZone)                    # 1 or 2 (QICK sets this through set_nyquist)
adc = rf.adc_tiles[0].blocks[0]           # ADC tile 0 (AMD tile 224), block 0 = ADC_D
print(adc.MixerSettings)                  # mixer configuration of the hardened DDC
print(rf.adc_tiles[0].PLLLockStatus)      # 2 means locked in the RFDC driver's convention

Properties correspond to the settings described in AMD's PG269 product guide . With QICK loaded, prefer QICK's own methods, which keep its cached settings consistent (Chapter 26).

The clocks: xrfclk

The xrfclk package programs the LMK and LMX clock chips from configuration files (exported from TI's TICS Pro tool), which is how PYNQ sets up the 4x2's sampling clocks at start-up . QICK calls it when it configures clocks, for example when you request an external reference . You rarely need it directly unless you change sample rates.

A first hardware test without QICK

In the lab

With the base overlay and its RF notebooks: connect DAC_B → 20 dB attenuator → ADC_D. Play a tone at 200 MHz, capture a buffer of ADC samples, plot it and its spectrum. Then sweep the tone from 10 MHz to 2 GHz and record the received power: this is your loopback transfer function, including both baluns. Repeat with the 20 dB attenuator replaced by a known filter to see the effect. Keep the notebook: it is your board's health check.

Suggested order

Week 1: Sets A and B. Week 2: Sets C and E, plus the 4x2 base RF notebooks. Week 3: Set F with your planned frequencies, Set G to see a full radio pipeline, then install QICK (Chapter 34). This gives you the SDR intuition the QICK documentation assumes.

Check yourself

1. Why does allocate() exist instead of just using a NumPy array?

Show answer
DMA engines need physically contiguous memory at a known physical address; ordinary NumPy arrays live in virtual memory that may be scattered. allocate() provides contiguous, DMA-accessible buffers that still behave like NumPy arrays.

2. Which SDR book notebook sets would you skip if short of time, and why?

Show answer
H (FEC) and most of I (OFDM) and D's BER material: they concern data communications, not qubit control or readout.
Summary
  • MMIO for registers (slow, configuration only); allocate + DMA for bulk data.
  • xrfdc exposes converter tiles and blocks; xrfclk programs clock chips; prefer QICK's methods once QICK is loaded.
  • Build a DAC→ADC loopback test as your board health check.
  • From the SDR book labs, sets A, B, C, E and F matter most for qubit work.
