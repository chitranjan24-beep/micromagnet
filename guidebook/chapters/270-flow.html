Why you need this

QICK ships ready-made firmware files for the 4x2, so you can do a great deal without ever opening an FPGA tool. Sooner or later, though, you may want something the standard firmware does not have: all four ADCs, a different sample rate, a custom real-time filter, a crosstalk matrix like spinQICK's. Then you need the design flow. This chapter explains what the files are, what each tool does, how long it takes, and what a QICK firmware project looks like, so you can judge when a change is a Python change and when it is a firmware change .

From block design to bitstream

  • Vivado is AMD's FPGA tool suite. Its IP Integrator lets you assemble a block design from IP blocks (the Zynq PS, the RF Data Converter, DMAs, custom blocks) and connect them with AXI interfaces; the design can be saved and recreated as a Tcl script.
  • Synthesis converts HDL into a netlist of device primitives.
  • Implementation places the primitives on specific sites and routes the connections, then performs static timing analysis. If any path is too slow for its clock, the design "fails timing" and must be changed (pipelining, different placement, lower clock).
  • The bitstream (.bit) configures the PL. The hardware handoff (.hwh) is an XML description of the block design: which IP blocks exist, their names, addresses and parameters.

Overlays: PYNQ's name for firmware

In PYNQ, an overlay is a bitstream plus its .hwh. When Python loads it, PYNQ programs the PL and parses the .hwh so that every IP block becomes a Python object with its registers mapped at the right address . QICK builds on this: QickSoc('qick_4x2.bit') loads the overlay, discovers the generators, readouts and buffers from the hardware description, and builds the configuration you see when you print soc . Swapping overlays takes seconds, so you can keep several firmware variants on the SD card.

A QICK firmware project

The QICK repository contains, under firmware/projects/, one directory per board and processor version, for example qick_tprocv1_4x2_standard and qick_tprocv2_4x2_standard. Each holds :

  • proj.tcl: creates the Vivado project and adds sources;
  • bd_2023-1.tcl: recreates the block design (for Vivado 2023.1);
  • ios.xdc, timing.xdc: pin assignments and timing constraints;
  • out/: the pre-built qick_4x2.bit and .hwh.

The custom IP (tProcessor, signal generators, readouts, buffers) lives in firmware/ip and firmware/hdl, with testbenches for simulation. Reading the block-design Tcl file is the most reliable way to see what a firmware contains. For example, the 4x2 tProc v2 standard design instantiates two axis_signal_gen_v6 generators, three axis_dyn_readout_v1 readouts, two averaging buffers, a weighted buffer, a DDR4 buffer, a multi-rate buffer and a time tagger .

In the lab

Before building your own firmware, ask on the QICK community channels and check the QICK and spinQICK repositories: many variants already exist, for example spinQICK's 16-output ZCU216 firmware and its crosstalk-compensation build . Building QICK firmware needs a Linux or Windows workstation with Vivado installed (tens of GB) and several hours per build. Check that your Vivado edition supports the XCZU48DR device: large RFSoC devices typically need a paid licence edition, and AMD's University Program can help academic users with licences.

Check yourself

1. What two files make a PYNQ overlay, and what does each contain?

Show answer
The .bit bitstream (the PL configuration) and the .hwh hardware handoff (an XML description of the IP blocks, addresses and parameters that Python uses to build drivers).

2. You want the tProcessor to apply a crosstalk matrix to two DAC outputs in real time. Python change or firmware change?

Show answer
Firmware: real-time arithmetic on output samples needs new logic in the generator data path (as in spinQICK's crosstalk firmware). With only two outputs you could instead precompute compensated waveforms in Python, which is a Python-only change.
Summary
  • Vivado turns HDL, IP and block designs into a netlist (synthesis), a placed and routed design (implementation, with timing checks), and a bitstream.
  • A PYNQ overlay is .bit + .hwh; QICK reads the .hwh to discover its blocks.
  • QICK firmware projects are Tcl scripts per board; pre-built 4x2 bitstreams are included.
  • Most experiment changes are Python changes; new hardware features need a firmware rebuild.
