Why you need this

QICK turns an RFSoC board into a qubit controller. To write good experiments with it, and to understand its limits on the 4x2, you need a clear picture of its parts: the timed processor that schedules everything, the signal generators that make the pulses, the readouts that demodulate, the buffers that store results, and the Python library that ties them together. This chapter gives that picture, based on the QICK papers, documentation and firmware source .

What QICK is

The Quantum Instrumentation Control Kit was developed at Fermilab with Princeton and other partners and published in 2022 . It consists of firmware for the ZCU111, ZCU216 and RFSoC 4x2 boards, the qick Python package, demo notebooks, and an optional custom analog front end. It is open source (MIT licence). As of October 2026, QICK's own list counts 91 papers that used it, 59 of them on superconducting circuits and 4 on quantum dots , and several companies sell QICK-based systems.

The tProcessor: a clock for everything

The tProcessor is a small custom processor in the FPGA. Its key idea is the separation of execution from timing: instructions run as fast as the processor can go, but the commands they issue (play this pulse, trigger that readout, set this pin) carry a timestamp and are queued in FIFOs. A dispatcher compares each timestamp with a running time counter and releases the command exactly when its time comes . So you program a timeline, and loops, branches and arithmetic happen "ahead of time", as long as the processor stays ahead of the schedule.

The QICK repository provides both tProc v1 and tProc v2 standard firmware for the 4x2 . New work should use tProc v2; spinQICK V2 is built on it . In the 4x2 tProc v2 standard design, the processor is configured with 5 waveform output ports, 14 trigger outputs, 3 input ports, a program memory of \(2^{12}\) = 4096 instructions and a data memory of \(2^{14}\) words .

Signal generators

A signal generator turns a timed command (frequency, phase, gain, envelope address, length, mode) into DAC samples. The flagship SG-v6 generator, used for both DACs in the 4x2 standard firmware, has :

  • a 32-bit DDS for frequency and phase, computing 16 samples per fabric clock cycle;
  • envelope memory for complex (I/Q) envelopes of up to 65 536 samples (about 6.7 µs at 9.8304 GSPS on the 4x2);
  • output styles: const (DDS × constant), arb (DDS × stored envelope), flat_top (stored rise and fall around a constant middle), plus a periodic mode for continuous tones;
  • a queue for upcoming pulses, so back-to-back pulses play seamlessly.

Other generator types appear in firmware for larger boards: sg_int4_v2 (4× interpolated, longer envelopes at lower bandwidth), sg_mux8 and sg_mixmux8 (up to 8 simultaneous fixed tones on one DAC, for multiplexed readout) .

Readouts and buffers

A readout block takes the full-rate ADC stream, mixes it with its own DDS, filters and decimates (by 8 on the 4x2) . Variants differ in who configures them: axis_readout_v2 is configured from Python before a run; axis_dyn_readout_v1 (in the 4x2 tProc v2 firmware) can be reconfigured by the tProcessor shot by shot, so readout frequency and phase can change during a sequence .

After the readout come the buffers :

  • Average buffer: on each trigger, accumulates the samples of the readout window into one I/Q value (the accumulated buffer), and can also store the decimated samples themselves (the decimated buffer).
  • Weighted buffer: applies a weighting function during accumulation (matched filtering, Chapter 23).
  • DDR4 buffer: streams decimated data into the 4 GB PL DDR4 for long records.
  • Multi-rate (MR) buffer: captures short raw records.
  • Time tagger: records the times of threshold crossings (used for photon counting).

Feedback

Each readout's accumulated result can be sent to a tProcessor input port. A program can wait for it, read it into registers (I and Q), compare it with a threshold and jump. The QICK tutorials show conditional pulses and active reset built this way, after measuring the readout latency so that the program waits long enough before reading . The total latency from the end of a readout window to a conditional pulse is a few hundred nanoseconds, set by the readout pipeline and the processor.

The Python side

  • QickSoc (on the board) loads the firmware, configures clocks and converters, and creates drivers for every QICK block. It is also a QickConfig: a description of the firmware (channels, clocks, memory sizes) that can be sent to a remote PC.
  • Program classes such as AveragerProgramV2 describe an experiment: in _initialize() you declare channels and define pulses and readouts; in _body() you write one shot's timeline. Loops and sweeps (add_loop, QickSweep1D) run in hardware.
  • acquire() returns accumulated results (averaged, or per shot with thresholding); acquire_decimated() returns time traces .
  • Units are human-friendly: frequencies in MHz, times in µs, phases in degrees, gains from −1 to 1. The library converts and quantises them; get_pulse_param() returns the values actually used.
Check yourself

1. Why can a tProcessor program contain loops and arithmetic without disturbing pulse timing?

Show answer
Because commands carry timestamps and wait in FIFOs; the dispatcher releases them at their scheduled times. The processor only needs to issue each command before its time arrives.

2. What is the difference between the accumulated and decimated buffers?

Show answer
The accumulated buffer stores one integrated I/Q value per readout trigger (per shot); the decimated buffer stores the time-domain I/Q samples within the readout window, for looking at waveforms.
Summary
  • QICK = firmware (tProcessor, generators, readouts, buffers) + Python library + demos, open source.
  • The tProcessor schedules timestamped commands; tProc v2 has a 48-bit time counter, 72-bit instructions, a call stack and an RNG.
  • SG-v6 generators: 32-bit DDS, 16 samples/cycle, 65 536-sample envelopes, const/arb/flat-top pulses.
  • Readouts mix, filter, decimate; buffers accumulate, store traces, or capture long records; results can feed back to the tProcessor.
  • Python describes experiments in _initialize() and _body(), with sweeps in hardware and human units.
