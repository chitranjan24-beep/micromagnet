Why you need this

This chapter is the practical bridge between the board and QICK: which firmware to use, how to install the library, what the configuration printout means line by line, which SMA connector is which channel, and the numbers that set the limits of your experiments (sample rates, frequency steps, memory sizes, buffer lengths). All values are from the QICK source and documentation as of October 2026 (software 0.2.436); check your own printout, because they change between firmware builds .

The firmware type bundled with the library was checked from its hardware description, which instantiates the tProc v1 core (axis_tproc64x32_x8) . The QICK tutorials state that the tProc v2 notebooks "must be run with a tProc v2 firmware" . A software emulator of the firmware (QickEmu) is under development on a separate branch of the QICK repository and lets you try the v2 tutorials without a board.

Installing QICK on the board

  1. Flash the PYNQ image QICK supports (for the 4x2, PYNQ 3.0.1; PYNQ 3.1 is not supported at the time of writing) .
  2. Copy or clone the QICK repository onto the board (for example into /home/xilinx/jupyter_notebooks/qick).
  3. Open qick_demos/000_Install_qick_package.ipynb and run it. It installs the library with pip3 install --no-index --no-build-isolation -e ../: the options let it work without internet and stop pip from replacing the board's PYNQ library .
  4. Restart the kernel, then create the SoC object:
from qick import *
soc = QickSoc()          # default: bundled tProc v1 firmware for this board
# soc = QickSoc('/home/xilinx/firmware/qick_4x2_tprocv2.bit')  # your tProc v2 build
soccfg = soc
print(soccfg)

Line by line:

  • tProc dispatcher timing 409.6 MHz: the tProcessor's time grid, 2.44 ns per tick.
  • RF reference 491.52 MHz: the reference the converter tiles multiply (×20 for the DACs, ×9 for the ADCs).
  • Groups of related clocks: the tProcessor and both DAC tiles share one clock group; the ADC tile is in another. Timing between groups has fixed but calibration-dependent offsets.
  • DAC output power mode 20 mA: the RF-DAC current setting (the other legacy option is 32 mA; Gen3 also allows finer VOP control).
  • Generators: two SG-v6 generators at 9830.4 MSPS, 16 samples per 614.4 MHz cycle; 65 536-sample envelopes (6.667 µs); 32-bit DDS spanning the full 9830.4 MHz (both Nyquist zones). Generator 0 is DAC_B, generator 1 is DAC_A.
  • Readouts: two readouts at 4423.68 MSPS, decimated to 552.96 MSPS; each has 16 384 accumulated entries and 4096 decimated samples (7.4 µs); triggered by tProc output pins 14 and 15; their results can feed tProc inputs 0 and 1 for feedback. Readout 0 is ADC_D, readout 1 is ADC_C.
  • Digital outputs: PMOD0_0–PMOD0_7, timed by the tProcessor. External start: PMOD1_0.
  • DDR4 and MR buffers: a 1.07-billion-sample capture (1.94 s) and an 8192-sample raw capture, both wired to the two readouts.

The tProc v2 firmware has a different processor and readout type and somewhat different memory sizes, but the same generator count, DACs and sample rates: its block design contains two SG-v6 generators and three dynamic readouts, with the RF data converter set to 9.8304 GSPS (DAC) and 4.42368 GSPS (ADC) .

A first loopback test

Connect DAC_B → 20 dB attenuator → ADC_D. The following tProc v2 program (adapted from QICK's basic sequencing tutorial ) plays a 100 ns pulse at 200 MHz and records the averaged I/Q trace:

from qick import *
from qick.asm_v2 import AveragerProgramV2
import numpy as np, matplotlib.pyplot as plt

soc = QickSoc('qick_4x2_tprocv2.bit')     # path to your tProc v2 firmware
GEN, RO = 0, 0                              # DAC_B and ADC_D on the 4x2

class Loopback(AveragerProgramV2):
    def _initialize(self, cfg):
        self.declare_gen(ch=GEN, nqz=1)
        self.declare_readout(ch=RO, length=cfg['ro_len'])
        self.add_pulse(ch=GEN, name='p', style='const', freq=cfg['f'],
                       ro_ch=RO, length=cfg['len'], phase=0, gain=0.5)
        self.add_readoutconfig(ch=RO, name='ro', freq=cfg['f'], gen_ch=GEN)
        self.send_readoutconfig(ch=RO, name='ro', t=0)
    def _body(self, cfg):
        self.pulse(ch=GEN, name='p', t=0)
        self.trigger(ros=[RO], pins=[0], t=cfg['trig'])

cfg = dict(f=200.0, len=0.1, ro_len=1.0, trig=0.0)     # MHz and µs
prog = Loopback(soc, reps=1, final_delay=1.0, cfg=cfg)
iq = prog.acquire_decimated(soc, rounds=100)
t = prog.get_time_axis(ro_index=0)
plt.plot(t, np.abs(iq[0].dot([1, 1j]))); plt.xlabel('time (µs)'); plt.show()

With the trigger at 0, the pulse appears some hundreds of nanoseconds into the trace: that offset is the time of flight through the converters and cables (Chapter 36). Move trig so that the readout window covers the pulse, then switch to acquire() for one I/Q value per shot.

Common mistake

Copying demo notebooks written for other boards without changing channel numbers. Many QICK demos assume ZCU216 or ZCU111 channel numbers (for example "generator 6"); on the 4x2 standard firmware there are only generators 0 and 1. QICK's quick-start guide warns about this for the 4x2 .

Check yourself

1. You want a 6.2 GHz tone from DAC_A. What do you set, and what should you check?

Show answer
Generator 1 with declare_gen(ch=1, nqz=2) and freq=6200. Check the actual output power with a spectrum analyser (it is reduced and frequency-dependent in zone 2), and check images and spurs.

2. A sweep of 101 frequency points with 1000 shots each, using accumulated readout, needs how many accumulated-buffer entries per readout if every shot is stored? What does that imply?

Show answer
101 000, more than the 16 384 entries of the standard firmware's buffer. QICK must split the acquisition into chunks (it reads the buffer as it fills), or you average in hardware and store fewer entries.
Summary
  • The QICK library bundles tProc v1 firmware for the 4x2; tProc v2 firmware must be built or obtained separately and is recommended for new work.
  • Install with the 000_Install_qick_package notebook on PYNQ 3.0.1; QICK does not support PYNQ 3.1 yet.
  • Generator 0 = DAC_B, generator 1 = DAC_A, readout 0 = ADC_D, readout 1 = ADC_C; PMOD0_0–7 triggers.
  • Key limits: 9830.4/4423.68 MSPS, 2.3 Hz frequency steps, 2.44 ns time grid, 6.7 µs envelopes, 16 384-entry accumulated buffers, 1.94 s DDR4 capture.
